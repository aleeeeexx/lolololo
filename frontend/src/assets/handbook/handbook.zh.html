DubDub 使用手册

本手册说明如何注册、创建密钥、配置 CC Switch 与各客户端，以及生图、Grok 与排错。文末有「小白入门」概念科普。

本教程面向 DubDub AI中转站 用户。请先在本站注册账号，再通过「充值/订阅」或「兑换」开通额度。API 地址请使用本页自动显示的站点根地址（兼容 OpenAI / Anthropic 风格路径，如 /v1）。登录后也可在侧边栏「直接用」里先试用已绑定密钥的模型，不必先配客户端。

一、注册账号

  1. 打开本站 注册页面 注册账号。
  2. 登录后前往「充值/订阅」或「兑换」开通额度。若注册未开放或额度未到账，请联系站点管理员。

二、新建密钥

进入本站 API 密钥 页新建密钥。创建时按你要跑的模型选厂商与分组（以站内实际可选分组为准）：

密钥页还提供「使用密钥」和「导入到 CC Switch」，可按协议自动填好地址，减少手填出错。模型 ID 也可在「支持的模型」页复制。截图为操作示意，本站配色可能不同，步骤相同。

Claude / Claude Code厂商选 Anthropic，分组选带有 claude- 的
Codex / GPT厂商选 OpenAI，分组选带有 gpt- 的
Grok厂商选「其他」，分组选 grok
密钥建好后请立刻复制保存。后面在 CC Switch 里填的就是这串 sk- 开头的 Key。地址按客户端协议填写：Codex（Responses 原生）与 Claude Code 填站点根 {{API_BASE}}；多数 OpenAI Chat Completions 兼容客户端填 {{API_BASE}}/v1。详见下文 CC Switch 与 Claude Code 章节。

三、下载并安装 CC Switch

CC Switch 用来统一管理各 AI 编程工具的 API 供应商（Claude Code、Codex 等），避免手改 JSON / TOML。

本手册按 v4.x 编写（Linux AppImage 实测 v4.0.18，侧边栏橙色主题）。下载页：
github.com/farion1231/cc-switch/releases/tag/v4.0.18（也可取最新 v4）。

  • Windows：选 .msi
  • macOS：选 .dmg
  • Linux：可选 .AppImage / .deb / .rpm

四、CC Switch 注意事项

v4 主界面为左侧边栏：上方是各应用（Claude Code / Codex / …），下方是 MCP、Skills、提示词、会话、授权中心、用量统计、应用、设置。每个应用页顶部有模式标签：直连 / 路由 / 聚合。页头徽章显示当前真实模式（例如「直连 · DubDub」）。

1. 点标签 ≠ 切换模式

点击「直连 / 路由 / 聚合」只切换查看内容。真正切换模式，要点页面里写明后果的按钮，例如「开始路由」「切换到聚合模式」「回到直连」。以页头徽章为准，而不是当前点亮的标签。

2. 三种模式对比

模式请求怎么走适合
直连客户端直接连供应商，CC Switch 看不到请求正文流量日常单供应商（本站推荐起步）
路由经本机 CC Switch 转发；可协议转换、热切换、故障转移协议不兼容或需要 failover
聚合经本机路由，多家模型进同一选择器，按所选模型分发一会话混用多家；无 failover
  • 聚合目前主要支持 Claude Code 与 Codex；不提供故障转移。
  • 「完整 URL」「自定义 User-Agent」等选项标注为只在路由/聚合生效；直连模式下可忽略。

3. 其它重要提示

  • 重启：Codex 改模型列表后需重启 Codex；Claude Code 直连一般无需重启（以界面提示为准）。
  • 切换供应商：v4 只替换地址 / 凭据 / 模型等关键字段，其它配置尽量保留。
  • 用量：会话日志与经路由的请求都会记入左侧「用量统计」；直连时主要靠会话日志（本站后台「使用记录」仍以实际打到 DubDub 的请求为准）。
  • 首次打开 v4：可能出现「界面改版了」引导——用量统计与授权中心已移到左侧边栏。

4. 本站第三方卡怎么填

Codex上游格式选 Responses（原生）；Base URL 填 {{API_BASE}}（不要重复 /v1，除非表单明确要求）
Claude Code上游格式选 Anthropic Messages（原生）；请求地址填站点根 {{API_BASE}}（不带 /v1）；认证字段默认 ANTHROPIC_AUTH_TOKEN
OpenAI Chat 兼容其它走 Chat Completions 的客户端，Base URL 通常仍是 {{API_BASE}}/v1

5. 添加供应商（通用步骤）

  1. 侧栏选中目标应用（如 Codex / Claude Code）。
  2. 右上角橙色 +「添加供应商」→ 自定义或预设。
  3. 填写 Base URL / 请求地址与本站密钥，配置模型，保存。
  4. 在直连下列表中启用该供应商；确认页头徽章变为「直连 · …」。

五、配置 CC Switch（Codex）

原则：在侧栏点 Codex 再添加供应商——不跟「模型名字」走。在 Codex 里用 GPT / Grok，都进 Codex 页配置。

本站 Codex 推荐：上游 Responses（原生），Base URL {{API_BASE}}。直连启用后，常见会写入 ~/.codex/config.toml：wire_api = responses、base_url = {{API_BASE}}，以及 bearer token 相关字段（字段名以当前 Codex / CC Switch 版本为准，例如 experimental_bearer_token）。模型 ID 以站内密钥分组可用列表为准（示例可能是 gpt-5.6-sol 等，勿写死唯一模型）。部分模型不适合 chat/completions；Codex 请走 Responses。

1. 打开 Codex 页，添加供应商

侧栏点 Codex，再点右上角橙色「+ / 添加供应商」。

2. 选择「自定义配置」或适用预设

在「预设供应商」中选自定义配置（或你熟悉的预设），再手动填写必要字段。

3. 复制 DubDub 密钥

到站内 API 密钥 页复制 OpenAI / GPT 分组密钥（勿把完整密钥写进文档或截图）。

4. 填入地址、密钥与模型并保存

  • 供应商标识：小写字母/数字/连字符，如 dubdub / dubdub-gpt
  • 上游格式 / 接口格式：选 Responses（原生）（界面也可能写作 OpenAI Responses）
  • API Key：粘贴 DubDub 密钥
  • Base URL：填 {{API_BASE}}（Responses 原生一般不要再加 /v1，除非表单说明要求）
  • 模型配置：添加模型 ID 与显示名称（以站内可用为准）

保存后，在直连列表里启用该供应商，并重启 Codex 后再改模型或验证。

  3. CC Switch 配好或修改模型后，务必重启 Codex 客户端。

  2. 安装 Git：git-scm.com

直连成功后可检查 ~/.codex/config.toml 是否包含 wire_api = responses 与 base_url = "{{API_BASE}}"（具体键名随版本可能略有差异）。

Cursor / VS Code

若 CC Switch 提供「应用到编辑器插件」一类开关，打开后重启编辑器生效。

七、Claude Code 使用

Claude Code 走 Anthropic Messages 协议，地址用站点根 {{API_BASE}}，不要写成 {{API_BASE}}/v1（与多数 OpenAI 兼容客户端不同）。密钥须属于支持 Claude 模型的分组。

1. 安装

推荐官方安装脚本，或：

npm install -g @anthropic-ai/claude-code
claude --version

2. 用 CC Switch（推荐）

  1. 侧栏选 Claude Code → 右上角橙色「+ 添加供应商」。
  2. 请求地址填 {{API_BASE}}。
  3. 粘贴本站 Claude / Anthropic 分组密钥。
  4. 上游格式选 Anthropic Messages（原生）；认证字段默认 ANTHROPIC_AUTH_TOKEN。
  5. 可选：填写 Sonnet / Opus / Haiku / Fable / Subagent 等模型映射（站内模型 ID 以「使用密钥」或模型列表为准，例如 claude-sonnet-4-5、claude-haiku-4-5-20251001 等）。
  6. 保存，并在直连下启用；确认页头徽章类似「直连 · DubDub」。

直连切换后 Claude Code 一般无需重启（以界面提示为准）；不行就新开终端。

3. 手动配置备选

在 Claude Code 设置或环境中设置（请自行替换密钥，勿把真实密钥写进文档）：

export ANTHROPIC_BASE_URL={{API_BASE}}
export ANTHROPIC_AUTH_TOKEN=你的密钥

4. 验证

  • 终端进入项目目录运行 claude。
  • 或检查 ~/.claude/settings.json 的 env 是否包含 ANTHROPIC_BASE_URL 与 ANTHROPIC_AUTH_TOKEN。

5. 注意与排错

  • 用站点根地址，不要加 /v1；否则容易 404 或路径错乱（见 FAQ · 404 / 错误处理 · 404）。
  • 401 / 密钥无效：见 FAQ · 401 / 错误处理 · 401。
  • 429：见 FAQ · 429 / 错误处理 · 429。
  • 若 Messages 返回 502：按 错误处理 收集 X-Request-ID / X-Client-Request-ID、北京时间与模型名反馈管理员。

八、在 Codex 中使用 Grok

在 Codex 里用 Grok，仍进入侧栏 Codex 页添加供应商，并在模型配置里写入 Grok 的模型 ID；不要误以为点侧栏其它应用图标就能让 Codex 走 DubDub。

1）在 DubDub 新建密钥：厂商「其他」，分组 grok。

2）在 CC Switch 的 Codex 页添加/选中对应供应商，上游仍按 Codex 的 Responses 原生配置，Base URL 用 {{API_BASE}}。

3）在「模型配置」里添加模型 ID（以站内 grok 分组实际列表为准，勿沿用过期示例）与显示名称，保存后重启 Codex。

若要用终端里的 Grok Build 编程智能体对接本站，见 十一、Grok Build。

九、在 Codex 中生图

如果只是想在网页里生图，也可以使用侧边栏的「直接用」或「批量生图」（若站点已开放）。下面介绍的是给 Codex / Claude Code 使用的本地 skill。

  1. 下载 skill：dubdub-imagegen.zip
  2. 安装后，在用户级 AGENTS.md / agent.md 里写明：遇到生图任务使用该 skill。
  3. 在 DubDub 新建 gpt-image 相关密钥，写入 skill 目录的 config.json：
{
  "base_url": "{{API_BASE}}/v1",
  "api_key": "填入 gpt-image 的密钥",
  "model": "gpt-image-2.5-flare"
}

Claude Code 也可复用同一套 skill。当前平台上常见生图模型包括 gpt-image-2.5-flare、gpt-image-2.5-sunburst 等。

十、Grok 生图生视频

若你不想走 Codex 客户端，也可以用 OpenAI 兼容 HTTP 直接调本站网关，完成 Grok 文本对话、生图与生视频。密钥分组请选 grok（见 二、新建密钥 / 八、使用 Grok）。

下文模型 ID 为当前可用示例（如 grok-4.20-non-reasoning、grok-imagine-image、grok-imagine-video-1.5）。实际以 GET /v1/models 或站内 grok 分组列表为准，勿写死唯一模型。

准备

  1. 在 DubDub 新建 grok 分组密钥，立刻离线保存（形如 sk-你的密钥）。
  2. 终端里导出环境变量（名字任选其一）：
export GROK_API_KEY="sk-你的密钥"
# 或：export DUBDUB_API_KEY="sk-你的密钥"

公共约定

  • Base：{{API_BASE}}
  • 请求头：Authorization: Bearer $GROK_API_KEY、Content-Type: application/json

先看模型列表

curl {{API_BASE}}/v1/models \
  -H "Authorization: Bearer $GROK_API_KEY"

从返回的 id 里挑选你要用的文本 / 生图 / 生视频模型。

文本对话

接口：POST /v1/chat/completions。示例模型 grok-4.20-non-reasoning（以列表为准）：

curl -X POST "{{API_BASE}}/v1/chat/completions" \
  -H "Authorization: Bearer $GROK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-4.20-non-reasoning",
    "messages": [{"role":"user","content":"写一句噜噜向噜妹表白"}]
  }'

生图

接口：POST /v1/images/generations。示例模型 grok-imagine-image。常用字段：prompt（描述）、aspect_ratio（如 16:9）。

curl -X POST "{{API_BASE}}/v1/images/generations" \
  -H "Authorization: Bearer $GROK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-image",
    "prompt": "噜噜头顶小橘子，黄身3D水豚",
    "aspect_ratio": "16:9"
  }'

生视频（异步三步）

视频是异步的：先创建任务拿到 request_id，再轮询状态，最后下载成品。示例模型 grok-imagine-video-1.5。

1）创建任务 — POST /v1/videos/generations：

curl -X POST "{{API_BASE}}/v1/videos/generations" \
  -H "Authorization: Bearer $GROK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video-1.5",
    "prompt": "噜噜向噜妹表白，头顶带绿蒂小橘子",
    "duration": 10,
    "aspect_ratio": "16:9",
    "resolution": "720p",
    "generate_audio": true
  }'

成功时返回形如 {"request_id":"…"}。记下这个 ID。

2）轮询状态 — GET /v1/videos/<request_id>：

curl "{{API_BASE}}/v1/videos/" \
  -H "Authorization: Bearer $GROK_API_KEY"

当 status 为 done 时，响应里的 video.url 常常是相对路径（例如 /v1/videos/<id>/content）。请拼到站点根：{{API_BASE}} + 相对路径。

3）下载成品（同样要带 Bearer）：

curl -L "{{API_BASE}}/v1/videos//content" \
  -H "Authorization: Bearer $GROK_API_KEY" \
  -o out.mp4
下载与轮询都必须带 Authorization: Bearer …；相对 URL 不要直接丢进浏览器当公开链接用。

排错

  • 偶发返回 no available accounts：稍后再试或指数退避重试即可。
  • 401 / 404 / 429 等：见 十二、常见问题 与 十三、错误处理。
  • 模型名报错：回到 GET /v1/models，确认该 ID 仍在你密钥的 grok 分组内。

十一、在 Grok Build 中使用

Grok Build 是 xAI 提供的终端编程智能体，可在交互式界面（TUI）、无头脚本，或通过 ACP 接到其它应用里使用。要让它走 DubDub 的 grok 分组，不必登录 xAI 账号，按下面把自定义模型指到本站即可。

模型 ID 必须以站内 grok 分组实际列表为准，勿沿用过期示例。官方说明见 Grok Build 文档 与 更新日志。

安装

macOS / Linux：

curl -fsSL https://x.ai/cli/install.sh | bash

Windows（PowerShell）：

irm https://x.ai/cli/install.ps1 | iex

准备密钥

在 DubDub 新建密钥：厂商「其他」，分组 grok（见 二、新建密钥 / 八、使用 Grok）。立刻离线保存。

export DUBDUB_API_KEY="sk-你的密钥"

写入自定义模型

编辑用户级配置 ~/.grok/config.toml（Windows 为 %USERPROFILE%\.grok\config.toml）：

[model.dubdub-grok]
model = "填入站内 grok 分组的模型 ID"
base_url = "{{API_BASE}}/v1"
name = "DubDub Grok"
env_key = "DUBDUB_API_KEY"
api_backend = "chat_completions"

[models]
default = "dubdub-grok"

默认按 OpenAI 兼容的 Chat Completions，Base URL 用 {{API_BASE}}/v1。若该模型需要 Responses 原生协议，把 api_backend 改成 responses，并把 base_url 改成站点根 {{API_BASE}}（不要多写 /v1）。密钥不要写进配置文件，用 env_key 指向环境变量。

启动

cd your-project
grok inspect
grok

grok inspect 可确认当前目录读到了哪些配置。进入界面后用 /model 切换模型；无头模式示例：

grok -p "Explain this repo" -m dubdub-grok

注意

  • 改完 config.toml 或换模型后，重新开一次 grok。
  • 401 / 404 / 429：见 十二、常见问题 与 十三、错误处理。
  • 模型名报错：回到站内 grok 分组列表或 GET /v1/models，确认 ID 仍有效。

十二、常见问题

终端可用，客户端不可用？

多数是网络问题。请检查代理是否开启、是否为 TUN 模式，以及 Codex 客户端是否已在改配置后重启。

新模型已上线，但客户端/终端列表里没有？

例如 gpt-6-sol 已在 DubDub 可用，但本地列表未刷新时：

方式 1：在 CC Switch 的「模型配置」里加上新模型 ID（如 gpt-6-sol），启用该供应商后重启客户端。是否命中可到 DubDub 后台看请求记录。

方式 2：CLI 显式指定模型：

codex --model gpt-6-sol
场景建议
Claude Code 换供应商一般不用重启
Codex 客户端 / CLI改完配置后重启
编辑器插件打开「应用到插件」后重启编辑器
跨厂商模型（如 Codex 用 Grok）仍在侧栏 Codex 页添加供应商，用「模型配置」填写模型 ID

返回 401 或提示 API Key 无效

  • 检查密钥是否复制完整，前后是否带有空格或引号。
  • 检查密钥是否启用、是否已选择分组。
  • 确认客户端没有继续读取旧环境变量或旧配置文件。

更完整的排查步骤见 十三、错误处理 · 401 Unauthorized。

返回 404

  • OpenAI 兼容客户端一般使用带 /v1 的 Base URL（如 {{API_BASE}}/v1）。
  • Claude Code 一般使用不带 /v1 的站点根地址（如 {{API_BASE}}）。
  • 检查最终请求是否出现 /v1/v1/...。

更完整的排查步骤见 十三、错误处理 · 404 Not Found。

提示 model not found 或模型不可用

  • 模型名必须与密钥分组支持的 ID 完全一致，包括大小写、横线和版本号。
  • 不要照搬其他平台教程里的模型名。
  • 回到 DubDub「使用密钥」窗口重新生成配置，或在 CC Switch 的「模型配置」里按本站实际 ID 填写。

修改配置后仍然走旧地址

  • 完全退出客户端，而不是只关闭一个对话窗口。
  • 检查终端、系统环境变量和配置文件中是否同时存在两套地址。
  • Codex、Claude Code 等客户端修改配置后建议新建会话；Codex 客户端 / CLI 建议重启后再试（与 CC Switch v4 直连行为一致）。

请求成功但没有使用记录

确认客户端使用的是本站（DubDub / {{API_BASE}}）中转地址，而不是官方默认地址或其他服务商地址。等待几秒后刷新使用记录；仍未出现时，记录测试时间并联系管理员核查。

使用记录里出现 ×2 等倍率标记，是重复扣费吗

不是。这是长上下文档位标记：GPT 系约超过 27 万 token、Grok 系超过 20 万 token 的请求按更高档位计价。详见本站计费规则说明。

同样的对话，为什么这次比上次贵

常见原因：一是部分模型分时计价，高峰时段单价更高；二是本次请求缓存未命中，输入按正常价而不是缓存价计费；三是请求进入了长上下文档位。可以在使用记录明细里核对单价与倍率。

请求频繁返回 429

429 表示触发速率限制。每个密钥都有每分钟请求数与 token 数限制（滚动窗口）。降低并发、减少自动重试，或稍后再试；程序里建议对 429 做指数退避。分类表与退避建议见 十三、错误处理 · 429 Rate Limit。

模型名带 -fast、-flex、-flash 后缀是什么

  • -flash 是同家族的轻量快速版（如 glm-5.3-flash），单价显著更低。
  • -fast 与 -flex 是速度档位变体，分别更快更贵、更慢更便宜。
  • 详见本站计费规则与模型选型相关说明。

十三、错误处理

本页按本站当前接口与错误日志能力整理。请以实际错误正文和请求 ID 为准，不要只看 HTTP 状态码。日常配置与排错也可先看 十二、常见问题。

排查流程：看错误码 → 看请求 ID → 按原因处理。

优先保存：完整错误正文、北京时间（Asia/Shanghai）、模型名、客户端与版本、实际请求地址、以及响应头中的 X-Request-ID / X-Client-Request-ID。向管理员反馈时勿发送完整 API 密钥、Authorization、密码、验证码或含密钥的配置；需要区分密钥时只保留首尾少量字符。

快速判断

  • 客户端 / 请求：400 / 401 / 404 / 413
  • 额度 / 并发：429 / usage limit
  • 上游 / 容量：403 / 502 / 503
  • 流式 / 网络：stream / reset / GOAWAY
  • Cloudflare 入口：522 / 524 / cf-ray
  • 请求过重：压缩上下文 / 拆分任务

400 Bad Request

常见原因：JSON 格式错误、必填字段缺失或类型不对、协议路径与客户端不匹配、请求体未完整到达（例如 Failed to read request body）。

  • 对照站内「使用密钥」生成的配置与本手册 五、配置 Codex，确认 Content-Type、字段名与接口路径。
  • 若请求体被代理截断或上传中断，先检查网络与客户端超时，再重发完整请求。
  • 在修正配置之前，不要对同一错误连续重试。

401 Unauthorized

密钥错误、未携带、已停用，或 Bearer 格式不正确。也可先看 FAQ · 401。

  • 在站内 API 密钥 页确认密钥已启用，并已选择正确分组。
  • 请求头应为 Authorization: Bearer sk-...（注意 Bearer 与密钥之间有一个空格）。
  • 检查复制时是否带入首尾空格、引号，或客户端仍在读取旧环境变量 / 旧配置文件。
  • 核对 Base URL：OpenAI 兼容客户端用 {{API_BASE}}/v1；Claude Code 用站点根 {{API_BASE}}。

403 Forbidden

可能原因包括：余额不足、密钥过期、分组权限不足、IP / 内容策略拦截、模型未对当前密钥开放，或上游鉴权 / 地区异常。

  • 个人偶发：检查余额、密钥有效期、分组与模型权限，换一个已知可用的模型做短请求验证。
  • 多人同时出现：更可能是上游或入口侧限制，暂停批量重试，记录时间与请求 ID 后联系管理员。

404 Not Found

多为 Base URL / 路径错误、出现 /v1/v1/...、模型名写错，或 OpenAI 与 Anthropic 协议路径混用。也可先看 FAQ · 404。

  • OpenAI 兼容：Base URL 填 {{API_BASE}}/v1。
  • Claude Code：一般用根地址 {{API_BASE}}，不要再叠一层 /v1。
  • 模型 ID 以站内「使用密钥」窗口生成的配置为准，勿照搬其他平台教程。

413 Payload Too Large

请求体或上下文超过限制。错误正文里可能出现 too_big、maximum context length 等字样。

  • 压缩提示词、删除过长历史、拆分文件或减少附图。
  • 把大任务拆成多轮短请求，而不是一次塞满上下文。
  • 仅提高客户端超时不会改变大小上限。

429 Rate Limit

速率 / 额度 / 并发类限制。简要说明见 FAQ · 429。请按错误正文区分类型：

错误提示含义正确处理
API key 额度已用完当前密钥独立额度耗尽补充额度或换密钥
USAGE_LIMIT_EXCEEDED / The usage limit has been reached订阅或上游账号用量限制等待重置或调整用量计划
Concurrency limit exceeded / Too many pending requests并发或等待队列已满降低并发，稍后再试
Upstream rate limit exceeded上游临时限流指数退避；必要时换模型或分组

临时限流建议约 2 / 4 / 8 秒退避，并加少量随机延迟；不要无限重试。

流式断开 / Stream Error

常见提示包括 stream error、connection reset、GOAWAY、incomplete chunked encoding、unexpected EOF 等。

  • 半截流式输出不等于请求成功；以最终是否完整结束、以及站内使用记录为准。
  • 保存最后一段输出与请求 ID，重启客户端后再试。
  • 检查本地代理 / VPN 是否稳定；缩短上下文后做一次短测试。
  • 断开后不要快速连打重试。

负载过高 / 请求太大

  • 压缩上下文、拆分任务，优先使用流式输出。
  • 失败后等待 30–60 秒再试，避免在高峰瞬间叠加重试。

500 Internal Server Error

  • 偶发可做有限次重试（例如 1–2 次，带退避）。
  • 若持续出现，向管理员提供多个请求 ID、北京时间、模型与客户端信息。

502 Bad Gateway

  • 多为上游或中间代理异常：等待数秒后重试 1–2 次。
  • 可到站内使用记录 / 渠道相关页面查看近期状态（若后台有展示）。
  • 若大量用户同时出现 502：停止批量重试，联系管理员。

503 Service Unavailable

错误正文可能包含 no available accounts 等容量类提示。

  • 等待服务恢复后再试；连续并发重试通常无效，反而加重排队。

504 Gateway Timeout

  • 减小请求规模、开启流式输出、适当延长读超时。
  • 仅做有限次重试，并保留请求 ID。

522 Cloudflare Connection Timeout

Cloudflare 无法在时限内连上源站。这通常不是密钥写错。

  • 核对客户端最终请求域名是否为 {{API_HOST}}，本地代理是否改写了域名。
  • 保存页面上的 cf-ray（若有）与发生时间，便于管理员对照入口日志。

524 Cloudflare Timeout

Cloudflare 已连上源站，但源站响应过久。

  • 开启流式输出、压缩上下文、拆分大任务。
  • 避免在同一超大请求上反复硬重试。

Cloudflare 相关说明

本站公开入口主要为 {{API_BASE}}（经 Cloudflare）。出现带 cf-ray 的错误页时，可按层理解：

  • 522：CF ↔ 源站连通问题
  • 524：源站处理过慢
  • 413 / 429：仍按上文 payload / 限流规则处理，不要误当成「换域名就能好」

B. 什么是「终端」（小白必读）

终端（也叫命令行、CLI 窗口）是一个用文字跟电脑说话的窗口。你输入一行命令，按回车，电脑执行并打印结果。没有花哨按钮，但程序员常用它，因为指令精确、可复制、可重复。

平时你「双击图标」打开微信、浏览器，那是图形界面。终端不取代这些软件；它只是另一扇门。Claude Code、Codex 的 CLI 形态，就是要你在这扇门里输入 claude 或 codex，让助手在当前文件夹对应的项目里工作。

Windows按 Win+R，输入 cmd 回车；或在开始菜单搜「终端 / Terminal / Windows Terminal」。
macOS打开「终端.app」，或按 Command+空格 搜「终端」。
Linux用发行版自带的「终端」应用即可。

你会看到的东西：一行提示符（常含用户名、路径），光标在闪。常见入门动作：

  1. 输入 cd 再空格，再跟上项目路径，回车——意思是「走进这个文件夹」。（Windows 路径可能像 cd D:\work\my-app；macOS/Linux 像 cd ~/work/my-app。）
  2. 从手册复制一条命令，粘贴到终端（Windows 终端常是右键粘贴；macOS 用 Command+V），按回车执行。
  3. 若报错，先整段复制错误文字（别只截一半），再去 常见问题 / 错误处理 对照，或发给管理员时一并附上。

为什么 Claude Code / Codex 常要在终端里跑？因为它们需要一个「当前工作目录」当项目根，才能读你的文件、按你的授权改文件、跑构建或测试命令。图形扩展（VS Code / Cursor 插件）底层往往也在干类似的事，只是界面更友好。

C. AI 编程助手在干什么（对照网页聊天）

用网页版 ChatGPT / Claude 时，你多半是：自己打开文件 → 复制一段代码 → 粘贴到对话框 → 再把回答粘回去。助手看不到你整份项目，也不能直接在你电脑上保存文件。

编程代理（Claude Code、Codex）更像请了一个能进项目目录的帮手：在你授权后，它可以读多个文件、提出修改、写入磁盘、在终端执行命令，并根据结果继续迭代。你仍然负责审查改动是否合理。

本站 DubDub 不替代这些软件。它提供 API 中转地址和密钥，让你已安装的客户端连到本站当前可用的模型。装软件、改配置的逐步操作在前面章节；本章只帮你建立地图。

项目说明（总是带上的上下文）全局 ~/.codex/AGENTS.md + 仓库内层层发现的 AGENTS.md；可用 AGENTS.override.md 覆盖合并通常由根到近（越靠近当前目录越具体）；把它当成 Codex 侧的「项目宪法」
可复用工作流Skill：带 SKILL.md；全局常见 ~/.agents/skills，仓库 .agents/skills把多步流程打包，需要时再调用
外接系统在 config 里配置 MCP常与 Skill 搭配：Skill 描述流程，MCP 提供工具连接
安装现成工作流插件 / 定制包（进阶）官方 customization 常见顺序建议：先写好 AGENTS.md → 再 plugin/skill → 再 MCP → 再 subagents

H. Skill vs MCP vs 说明文件（对照）

三个东西经常被一起提到，但职责不同：

概念干什么Claude 常见位置Codex 常见位置
Skill可复用流程（按需）.claude/skills 或 ~/.claude/skills.agents/skills 或 ~/.agents/skills
MCP外接工具协议（连 Issue、设计稿、库表等）项目 .mcp.jsonconfig.toml 里的 MCP 配置
总是生效的说明项目「宪法」CLAUDE.md、.claude/rulesAGENTS.md（及 override）
设置 / 密钥 / 沙箱行为开关与凭据settings.json（及 local 覆盖）config.toml

记忆口诀：说明文件管「你是谁、项目规矩」；Skill 管「这套步骤怎么做」；MCP 管「能调用哪些外部工具」；settings/config 管「权限、地址、沙箱」。

I. 插件市场（Claude 为主，Codex 一句）

Claude Code：在会话中用 /plugin 浏览与管理。官方市场 claude-plugins-official 常会自动加入。安装示例形态：/plugin install 名称@claude-plugins-official（以你客户端实际提示为准）。

信任警告：插件可能在本机以你的用户权限执行代码或访问文件。只安装你理解来源与用途的组件；不确定就先不装，先用官方 CLI + 本站直连跑通主流程。

Codex：同样支持通过插件/定制安装现成工作流；优先把 AGENTS.md 写清楚，再按需加 skill / MCP / 插件，避免一上来堆扩展。

J. 完全小白的学习路径

  1. 注册账号并联系管理员开通额度。
  2. 新建密钥：按你要跑的工具选对厂商与分组，立刻离线保存。
  3. 安装 CC Switch（v4），阅读 直连 / 路由 / 聚合——先用直连。
  4. 学会打开终端，用 cd 进入一个真实小项目（或空练习目录）。
  5. 只配一个工具并跑通一次：Codex 见 配置 + 各端使用；Claude Code 见 Claude Code 章。成功标准：能对话，或安全地改一个无关紧要的小文件。
  6. 再学项目说明：Claude 写 CLAUDE.md / rules；Codex 写 AGENTS.md。
  7. 最后才加 Skill、MCP、插件。卡住时查 十二、常见问题 与 十三、错误处理。

若只要在其它聊天客户端里用 Grok 模型：建 grok 分组密钥，按 八、使用 Grok 配置即可；要用终端里的 Grok Build，见 十一、Grok Build。不必先装 Claude Code。

K. 安全与习惯

  • 密钥不要截图发群、不要写进公开仓库或手册示例；泄露后立刻在站内作废并换新。
  • 下载客户端过慢时可开系统代理，并尽量使用 TUN 模式。
  • 改 Codex 模型或供应商后重启 Codex；Claude Code 直连多数情况不用重启（以界面提示为准）。
  • 模型 ID 手打易错；优先从站内列表复制。
  • 不要对不明来源的仓库盲目信任项目级 .codex/config.toml、MCP 或插件。
  • 本站是中转：客户端版本、本机权限、代理与上游额度都会影响体验；排查时别只盯着密钥。
